# Lane and depth

This file is the only place in mneme's agent-facing text that states the numeric lane thresholds. Every other skill, the manuals and the subagent layer point here. When the rule changes, change it here.

## Trivial lane

A change is trivial only if all of these hold:

- at most 3 files, at most 20 changed lines;
- no SQL and no migrations;
- no changes under cmd, install or assets;
- no public API change (adding, removing or renaming an exported symbol counts).

Anything else is standard. The lane is proposed to the person and confirmed by them; it is never inferred.

## Declared scope

A trivial item carries a `scope` glob. The auditor checks every changed file against it. If the scope turns out too small, stop and report; do not widen it silently.

## When the change grows

- Before implementing starts: `lane_reclassify` to standard (the only direction allowed).
- After `lane_audit` fails: `lane_reclassify` to standard. `lane_override` with a written reason is the last resort, for example an autogenerated file.
- The engine that audits lives in Go (`internal/laneaudit`); this text is the documentation for agents.

## Orchestrator editing inline (opt-in)

By default the orchestrator never edits code a subagent owns. A project may allow it to edit inside the declared scope of a trivial spec in implementing with `[delegation] orchestrator_trivial_inline = true` (or per project under `[delegation.projects."<slug>"]`, or the env var `MNEME_DELEGATION_TRIVIAL_INLINE`). It stays off unless the person turned it on. Bash is not relaxed.

## Skipping stages

- Trivial lane skips the architect, the criteria document and the approval gate; the auditor replaces QA.
- Standard lane skips nothing. A stage nobody owns is supplied by the orchestrator, knowingly.
- Depth follows size, not risk. Weighing risk is not part of this rule yet.
