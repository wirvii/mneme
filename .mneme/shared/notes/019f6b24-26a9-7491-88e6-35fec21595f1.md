Verifiqué que `CreateWithID` con un id nuevo SÍ falla de forma segura (hay `UNIQUE INDEX idx_memories_upsert ON memories(topic_key, project, scope) WHERE topic_key IS NOT NULL`), pero el branch `existing != nil` (cuando el note foráneo reusa el MISMO id que el manifest local — el caso realista una vez que dos peers ya convergieron en el mismo id vía un import anterior, exactamente la situación de team-memory activo desde hace tiempo como en novo) SÍ llama `svc.Update` sin ningún check de topic_key y clobbea el manifest local en su sitio.
